## 共同口径

- 全书讲解工程方法及其背后的系统设计原则。实践暴露问题，评估检验方法，经过验证和抽象形成原则。
- `Agent = LLM + 上下文 + 工具` 是功能分解；`Agent = Model + Harness` 是实现分解。
- LLM 负责决策；上下文承载当前决策可用的信息；Harness 组织上下文和工具调用；工具或环境实际执行。
- 上下文比作当前决策视野，工具比作感官和手脚。具体观测不等于观测空间，接口不等于整个动作空间。
- 环境位于 Agent 外；Harness 位于 Agent 内、Model 外。部署位置不决定概念归属。
- Harness 保留上下文管理、工具接口、约束、验证、纠正五项功能。运行循环贯穿这些功能。
- 专业交互采用“观测”，人的查看行为采用“观察”。开放式不等于无权限或接口限制。
- 示例、真实运行、重复实验和作者判断分别交代依据。出版结论引用固定记录，不能只指向 `latest.json`。
- 保留必要的业务经历和判断；减少前置术语、重复定义、空泛过渡和翻译腔。正文沿具体问题推进。

## 教学文风与迭代要求

- 参照 AI Infra Book 的教学方式，从具体问题进入机制，沿输入、状态和设计选择展开；保留作者经历、案例和判断。
- 逐章反复修改：先调主线，再改段落和句子，最后核对图文与章间衔接。
- 用直接、肯定的定义说明技术边界。清理“不是……而是……”、自我否定、自我怀疑及免责声明式段落；避免新增同类表述。
- 实验在正文中呈现问题、关键现象和由此理解的机制，数据只保留论证所需部分。
- 固定记录路径、执行命令、API 字段、代码片段和复现细节放在实验 README；正文保持连续讲解。
- 安全约束、失败机制与适用条件仍通过具体设计说明，避免把技术内容误删为“免责声明”。

## 插图规则

所有示意图逐图重新设计，不能仅替换颜色。绘图源集中在 `scripts/book_figures/`，输出到 `book/images/`，沿用文件名以保持引用。图的用途与重绘状态记录在 `docs/figure-inventory.json`。

- 白底，文字与主要线条为深灰，最多三级浅灰填充。不依赖颜色区分信息。
- 统一中文无衬线字体与代码字体；在最终书页宽度下检查字号，不能以缩小文字解决内容过多。
- 每图回答一个明确问题。结构图表达边界，时序图表达先后，实验图表达条件与结果；不强求相同布局。
- 框线表示包含或归属，箭头表示明确的数据、控制或引用关系。不同线型在图注中说明。
- 图内保留对象、状态和关键数值，长解释写入正文或图注。
- 数值图说明单位、条件和证据；示意图标注是否按比例绘制。
- 图题由 Markdown 图片说明承载，不在图内或图后重复印一次。
- 原始截图、实测热图等证据图不得伪造成“重绘的真实结果”。逐图决定保留证据并另绘机制图，或改为明确标注的示意图；仍须核对灰度可读性。
