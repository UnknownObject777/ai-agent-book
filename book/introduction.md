# 前言 {.unnumbered}

2025 年 8 月至 2026 年年初，我开设了一门线上视频课程《Agent 实战营》。课程围绕一个问题展开：怎样用可解释、可验证、可复用的工程方法构建 AI Agent？跑通演示只是起点。我们还需要知道：为什么采用这个设计，它解决了什么问题，条件改变后是否仍然有效。本书由课程讲义和配套实验整理、补充而成，讨论 **Agent 的工程方法及其背后的系统设计原则**。

## 从真实业务中形成方法 {.unnumbered}

这些方法主要来自长流程、高风险业务。作为 Pine AI 的首席科学家，我与团队共同研发了 Pine，让 Agent 代表用户与真人沟通，处理账单协商、退款投诉和订阅取消等事务。这些任务直接涉及用户利益：数字算错、重复操作或过早结束任务，都可能造成损失。

把这些事情办好，需要系统持续跟进执行。一项任务可能持续数小时乃至数周，需要长时间通话、多轮邮件往来和复杂表单操作。等待期间，用户的要求可能改变，服务商也可能提出新的条件。系统必须保留进度、核实结果，并在出错后继续工作。这些要求不断暴露模型能力与业务需求之间的差距，也促使我们改进模型之外的工程。

- 为控制提示词增长，我们按需加载任务指令；为减少工具定义占用的上下文，我们让模型通过命令行使用部分能力。
- 为让模型掌握当前情况，我们用系统状态栏提供时间、环境和任务进度；对危险或越权操作，则由运行系统实施检查和限制。
- 为避免模型过早认为任务完成，我们采用本书所说的“提议者—审核者”方法，让另一角色依据产物和外部证据检查结果。

这些实践早于 Skill、Harness、Loop 工程等名称的流行。许多团队面对相似问题，也独立形成了相近的方法。**实践在前，命名在后。** 一个概念获得广泛认可，往往是因为它概括了已经反复出现的问题和解法。

我们通过多次运行和对照任务检验这些经验，辨别设计带来的改善。**评估帮助我们判断方法是否有效，以及改善了一类任务后，是否损害了另一类任务。** 第 7 章将专门讨论如何建立这样的反馈。

真实业务暴露问题，工程实践形成方法，评估检验方法；经过反复验证和抽象，才逐步沉淀为可复用的系统设计原则。具体手段会随模型升级而改变，基本问题却会长期存在：模型需要哪些信息，系统允许哪些操作，结果怎样验证，失败后怎样恢复。这也是我所说的“好的设计原则能够穿越模型迭代周期”。

> **本书也是一次人机协作实践**
>
> 从构思到书稿迭代，我主要采用口述式协作（whisper coding），与 Pine 的语音 Agent 一起整理资料和文本。准备课程时，我先口述提纲，由 Agent 调研并形成草稿；课程结束后，再结合学员反馈核查论证、案例和实验。口述降低了把想法转成文字的成本，也缩短了修改周期。除了《Agent 实战营》，我还于 2024—2026 年在中国科学院大学讲授 Agent 实践课程，相关经验也融入了本书。选择开源发布，是希望这些知识能够服务更多研究者与工程实践者，并在使用与反馈中继续完善。

## 本书的出发点 {.unnumbered}

本书希望帮助你理解 Agent 的基本结构、构建方法与能力边界，并据此设计能够可靠执行任务、持续改进的系统。

我们用一个公式概括本书讨论的 LLM Agent：

**Agent = LLM + 上下文 + 工具。**

LLM（大语言模型）负责理解、规划和决策；上下文承载当前决策所需的信息；工具连接 Agent 与外部环境，用于获取观测或执行行动。图0-1概括了这三类功能。

![图0-1 Agent 的三类功能：模型作出决策，上下文承载信息，工具提供与环境交互的接口](images/fig0-1.svg)

可以把 LLM 比作“大脑”，把上下文比作“当前决策视野”，把工具比作“感官和手脚”。这组粗略比喻帮助我们理解三者的协作：工具定义本身也在上下文中，读取工具既需要模型发出调用，也会带回新的信息。

熟悉强化学习的读者可以作一个粗略类比：模型承担类似策略的决策功能，上下文承载具体观测与历史，工具提供观测和动作接口。观测空间与动作空间描述可能看到什么、选择什么；一次调用则使用其中的具体信息和行动。第 1 章将进一步说明这些边界，以及生产系统如何用 Harness 组织模型运行。

> **从生命到设计实体**
>
> 除了工程价值，Agent 也引出了更远的思考。Richard Sutton 曾用尘埃、恒星、生命和“设计实体”（designed entities）描述宇宙发展的几个阶段。[^fm-sutton] Agent 可以被视为设计实体的一种形态：它能够生成代码，参与构建新的 Agent，也可能帮助改进自身所在的系统。这种参与构建和改进的能力，为自举和持续进化提供了探索方向。第 5、9、10 章将分别从代码生成、持续更新和多 Agent 协作讨论这些可能性。

[^fm-sutton]: Richard Sutton 在 Dwarkesh Patel 访谈中讨论了“设计实体”，见[访谈视频约第 59 分钟](https://www.youtube.com/watch?v=21EYKqUsPfg&t=3463s)。

## 全书结构 {.unnumbered}

本书共 10 章，可归入两个部分，围绕两个相互衔接的问题组织（图0-2）。**第一部分“如何构建 Agent”**，包括第 1 ～ 6 章：先建立 Agent 的基本结构和运行机制，后续依次讨论上下文、记忆与知识、工具、Coding Agent，以及观测与动作空间的扩展。**第二部分“如何提升 Agent 能力”**，包括第 7 ～ 10 章：先用评估建立可度量的反馈，再通过模型后训练、基于运行经验的持续进化和多 Agent 协作，分别从模型参数、单体系统和群体系统三个层面扩展能力。

![图0-2 全书结构：如何构建 Agent 与如何提升 Agent 能力](images/fig0-2.svg)

- **第 1 章 AI Agent 入门**回答 Agent 是什么，以及一个能运行的 Agent 如何走向可靠的系统。本章从核心组成和运行循环出发，逐步讨论 Harness、编排与安全，为后续各章建立统一的概念框架。
- **第 2 章 上下文工程**讨论 Agent 在一次任务中能够看到什么，以及这些信息应如何组织。本章沿着“构造上下文—提高信息利用效率—控制上下文增长”的主线展开，说明为什么上下文需要作为一个整体进行系统设计。
- **第 3 章 用户记忆和知识库**讨论 Agent 如何跨越单次会话，保存用户信息并利用知识库。本章从用户记忆进入知识的检索、组织与更新，说明如何建立可检索、可审查、可持续维护的持久化知识体系。
- **第 4 章 工具**讨论 Agent 如何安全、有效地连接外部世界。本章从工具的分类和设计原则出发，进一步讨论工具的互操作、发现与安全机制，说明工具如何决定 Agent 的能力边界并影响系统安全。
- **第 5 章 Coding Agent 与通用 Agent**讨论为什么 Coding Agent 与文件系统的结合正在成为通用 Agent 的重要技术基础。本章从 Coding Agent 的工作方式出发，考察代码在编程之外的多种用途，说明代码生成如何成为 Agent 执行任务和扩展能力的重要手段。
- **第 6 章 交互：观测与动作空间的扩展**讨论当外部世界不再按照一问一答的节奏等待 Agent 时，系统应如何持续感知并及时行动。本章通过异步事件、语音、Computer Use 和机器人操作逐步扩展交互边界，并总结这些场景共有的交互与控制问题。
- **第 7 章 Agent 的评估**回答如何判断一次改动使 Agent 变好了还是变差了。本章从成功标准出发，沿着评估环境、数据、方法和迭代决策建立闭环，将评估转化为驱动系统改进的反馈机制。
- **第 8 章 模型后训练**讨论何时需要通过后训练更新模型参数，重点讲解有监督微调（SFT）和强化学习（RL）分别适合解决什么问题。为厘清后训练的作用与边界，本章先简要回顾预训练和中期训练（mid-training），再讨论训练数据、奖励环境和算法选择如何影响后训练效果，以及为什么数据和环境往往比算法更关键。
- **第 9 章 Agent 的持续进化**讨论如何把 Agent 的运行经验转化为下一版本的能力。本章沿着“获得学习信号—选择更新载体—验证并发布更新”的主线展开，建立一套可追溯、可验证、可回滚的持续更新机制。
- **第 10 章 多 Agent 协作**讨论多个 Agent 何时真正优于单个 Agent，以及它们应当如何分工、通信和相互验证。本章结合上下文共享方式与协作结构，分析新信息、并行执行和相互验证带来的收益，说明如何通过信息共享、任务分工和控制机制实现有效协作。

## 如何阅读本书 {.unnumbered}

全书整体上逐层展开，但各章也具有一定的独立性，你可以根据自己的需求选择不同的阅读路径。

- **如果你希望系统掌握 Agent 开发**，建议按顺序阅读全书：第 1 ～ 6 章系统讲解 Agent 的构建方法，第 7 ～ 10 章进一步讨论如何评估、提升和扩展 Agent 的能力。
- **如果你希望快速掌握全书主线**，建议优先阅读第 1 章、第 2 章、第 4 章、第 7 章：第 1 章建立全局认知，第 2 章和第 4 章分别讨论上下文与工具，第 7 章说明如何通过评估推动系统改进。第 2 章中 KV 缓存的底层原理技术性较强，初次阅读可先跳过，只需掌握开头给出的三条核心结论，不影响后续理解。
- **如果你关注模型后训练**，建议重点阅读第 7 章（Agent 的评估）和第 8 章（模型后训练），如果此前缺少 Agent 开发经验，可先阅读第 1 章和第 2 章，了解 Agent 的基本组成和运行机制。

### 前置知识 {.unnumbered}

本书面向有一定技术背景的读者，但不要求你是某个特定领域的专家。以下按“必需”和“推荐”两个层次列出前置知识，帮助你评估自己的准备程度。

#### 阅读全书的基础 {.unnumbered}

- **Python 编程**：书中几乎所有实验都基于 Python。你需要熟悉 Python 的基本语法、常用数据结构，以及包与依赖管理（如使用 pip 安装依赖）等基本知识。不要求精通，但应能读懂和修改中等复杂度的 Python 代码。
- **LLM 产品使用经验**：你应该使用过 ChatGPT、Claude 或类似产品，理解“提示词→模型回复”的基本交互模式。
- **软件工程常识**：熟悉命令行操作、Git 版本控制、JSON 数据格式、REST API 等基本概念。这些知识是获取和运行实验代码、理解 Agent 工具调用机制的基础。

#### 有助于理解特定章节的知识 {.unnumbered}

- **机器学习基础**（第 8 章）：了解训练与推理、损失函数、梯度下降、过拟合等基本概念，有助于理解模型后训练。
- **线性代数基础**（第 2 章、第 3 章、第 8 章）：对向量和矩阵有直观的理解（比如知道向量可以表示方向和大小、矩阵可以进行批量运算），有助于理解嵌入和注意力机制。
- **概率统计基础**（第 8 章）：了解概率和期望等基本概念，有助于理解强化学习中的期望奖励。书中的数学侧重直观解释，不涉及复杂推导。
- **Web 开发基础**（第 6 章）：了解 HTTP、WebSocket、前后端分离架构等概念，有助于理解事件驱动的异步 Agent 架构和语音 Agent 的实时通信实验。
- **对 Transformer 架构的基本了解**（第 2 章、第 8 章）：当前绝大多数主流 LLM 都以 Transformer 架构为基础。对于希望系统补充 LLM 基础知识的读者，推荐阅读《图解大模型：生成式 AI 原理与实战》（Jay Alammar、Maarten Grootendorst 著，李博杰译，图灵教育出品）。该书以直观的图解方式讲解 Transformer 架构、预训练与微调等核心概念，与本书的 Agent 工程视角形成良好的互补。

具备基本编程能力，就可以从第 1 章开始学习 Agent 工程。阅读后续章节时，再按需补充相关的数学和机器学习知识。

### 实验、思考题及随书代码 {.unnumbered}

本书的每章都包含大量的**实验**和**思考题**。实验按“实验 *X*-*Y*”编号，其中 *X* 为章号，*Y* 为章内序号。实验和思考题的标题中用星级标注了难度：★ 表示入门级，适合所有读者；★★ 表示中等难度，需要一定的工程实践基础；★★★ 表示较高难度，适合进阶挑战，通常涉及开放性问题或复杂的系统设计。大部分实验配有完整的可运行代码，组织在配套的开源仓库中：[https://github.com/bojieli/ai-agent-book](https://github.com/bojieli/ai-agent-book)。

配套仓库按章节和实验编号组织代码，各实验的 README 提供环境配置、运行步骤和完整记录。建议你亲手运行实验，修改输入或条件，看看 Agent 的行为怎样随之改变。许多设计直觉会在这样的对照与调试中逐渐形成。

> **提示｜AI 辅助编程工具**
>
> 建议在完成实验时使用至少一款 AI 辅助编程工具，如 Claude Code、Codex、Cursor、TRAE 等。一方面，这些工具能显著提高书中实验的开发效率，因为实验涉及大量代码编写和调试。另一方面，这些编程工具本身就是成熟的 Coding Agent，你在使用它们的过程中会直观地体验到 ReAct 循环、工具调用、上下文管理等书中反复讨论的核心机制。这种第一手体验对理解 Agent 的工程方法及其背后的系统设计原则极有价值。

Agent 技术仍在快速演进，但**好的系统设计原则具有穿越时间的力量**。掌握了“为什么要这样设计”，你就能在技术浪潮的变化中保持清醒的判断力。希望这本书能成为你构建 Agent 的可靠指南。
